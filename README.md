# Revita → Temu · GitHub scraper

Скрейпърът обхожда само седемте посочени страници за марки, всичките им страници с продукти и откритите от тях продуктови адреси:

`alive`, `natures-way`, `double-wood`, `barbel-drexel`, `now-foods`, `natural-factors`, `webber-naturals`.

Използва директни HTTP заявки. Не изисква Chrome, Selenium, вход в профил, API ключове или платени услуги. Не преодолява CAPTCHA: при блокирана страница записва грешка. Разработката и приложените проверки използват предоставения HTML; сайтът не е сканиран по време на създаването на този пакет.

## Стартиране в GitHub

1. Разархивирай ZIP файла.
2. Създай GitHub repository. Качи **съдържанието** на папката `revita-temu-scraper` в основната директория. Там трябва да са `revita.py`, `config.json`, `requirements.txt`, `templates`, `tests` и `.github`.
3. Ако `.github` не се вижда, включи показването на скрити файлове. Провери, че в repository съществува `.github/workflows/scrape.yml`. Можеш да го добавиш и чрез **Add file → Create new file**, с този пълен път.
4. Отвори **Actions → Revita Temu Export → Run workflow**. Остави `limit = 0` и `offline` изключено за целия каталог.
5. След изпълнението отвори съответния run. В **Artifacts** изтегли `revita-temu-results`.

За бърза проба задавай `limit = 10`. Това ограничава продуктовите страници, но продължава да открива всички адреси от седемте марки. С `offline` включено се проверява само предоставеният продукт Alive; няма заявки към сайта.

Workflow се стартира ръчно. Няма автоматично качване на продукти в Temu и няма автоматичен седмичен график.

## Резултати

| Файл | Съдържание |
| --- | --- |
| `TEMU_REVITA_001.xlsx` | Попълненият оригинален Temu шаблон; данните започват от ред 5 |
| `TEMU_REVITA_002.xlsx`, … | Допълнителни части при повече от 4996 реда |
| `catalog.json` | Извлечени продуктови данни, състав, производител, снимки, наличност |
| `review.csv` | Липсващи задължителни данни, несъвпадения с падащите менюта и приложени настройки |
| `errors.csv` | Неуспешни категории, продуктови заявки, вариации или попълване |
| `coverage.json` | Брой обработени страници и открити продукти за всяка марка |
| `summary.json` | Общи броеве, пълнота на обхождането и нужда от преглед |
| `discovered_urls.json` | Всички уникални открити продуктови адреси |

При грешка GitHub run се маркира като неуспешен, но резултатите и диагностиката се запазват. Неуспешни продукти не се заменят с измислени данни. Не качвай частичен каталог като пълен; провери `errors.csv` и `summary.json`.

## Логика на попълване

- Обхожда `href` и `data-href` в страницирането, включително `span#infinity-url`. Взима продуктите само от основния списък, а не от препоръчани продукти в страницата.
- Продукт в повече от една марка се записва веднъж. SKU използва вътрешния продуктов ID; референцията на магазина се пази в отчета.
- `Base Price - EUR` = текущата цена. `List Price - EUR` = старата цена; без намаление използва текущата. EUR цените не се преобразуват. BGN се преобразува само ако валутата е изрично разпозната в HTML.
- Налични продукти получават конфигурирания запас; неналични и продукти с неизвестна наличност получават 0. Скрейпърът няма достъп до реалната складова бройка.
- Категорията се избира **само от приложения шаблон**, първо по заглавие, после по състав. При няколко съвпадения или липса на пряко съответствие избира най-близката налична и добавя запис за преглед. Няма празни категории. За продукт извън обхвата на категориите тази стойност трябва да се прегледа.
- Извлича високорезолюционните снимки само от основната продуктова галерия. Всеки URL е в отделна колона. Изображенията остават както са; съдържанието им не е оценявано автоматично.
- Описанието включва име, марка, състав, указания, предупреждения и производител. Не копира цели рекламни/лечебни абзаци и въпроси от посетители. Оригиналното име се запазва, но не се гарантира одобрение от Temu.
- При комбинации в продуктовата форма заявява вариантите чрез PrestaShop refresh endpoint и прави отделни редове с техни цени и наличност. Ако endpoint или отговорът е различен, записва грешка, вместо да представя всички варианти с цената на основния продукт. Това е проверено със симулиран отговор; предоставеният продукт няма варианти.
- Запазва всички останали части на оригиналния XLSX, включително скритите листове, падащите менюта и резервираните редове. Не добавя чужди стойности в менюта.

## Конкретни ограничения на приложения шаблон

В падащото меню `Brand` са налични само `NATURAL FACTORS` и `WEBBER NATURALS`.

В `Manufacturer` са налични:

`NOW Health Group, Inc`, `WN Pharmaceuticals Ltd.`, `Natural Factors Nutritional Products Ltd`, `HERBALKAN`, `A - JAR`, `Балкан Лидер Груп ЕООД`.

По твое указание продуктите на **Alive/Nature's Way, Double Wood и Bärbel Drexel се включват в общия Temu файл с празни колони Brand и Manufacturer**. Свързаното поле Trademark също остава празно. Не се изключват и не се отделят в друг файл заради тези празни полета. Марката и източникът на производителя се запазват в описанието и данните за справка. Това се управлява от `blank_brand_and_manufacturer` в `config.json` и има предимство пред индивидуални корекции на тези полета.

Единственото налично EU responsible person е `Geo Nutrition LTD.`. Не е потвърдено, че представлява тези марки, затова полето е празно по подразбиране. Може да се зададе само при потвърдено съответствие. Страната на произход се попълва от изрично обозначена страна в страницата или твоя корекция; адресът на производителя не се приема за страна на произход. Дати на производство/годност и срок на годност не се измислят.

## Настройки и корекции

В `config.json` началните оперативни настройки са:

| Настройка | Стойност | Значение |
| --- | --- | --- |
| `stock_if_available` | 20 | Предполагаем запас за наличен продукт; не е извлечена складова бройка |
| `default_weight_g` | 1000 | Временно брутно тегло за доставка, в грамове |
| `default_dimensions_cm` | `[20,20,20]` | Временни пакетни размери, в сантиметри |
| `shipping_template` | `Magazin` | Наличен шаблон за доставка от файла |
| `handling_time` | `2 Days` | Време за обработка |

Теглото за доставка не се приравнява на дозата/нетното съдържание. Тези стойности са настройки, не проверени продуктови факти; прилагането им се вижда в `review.csv`. Задай реалните размери и тегла чрез корекции.

Можеш да добавиш корекция по **референция на магазина** или **пълен продуктов URL**. Например:

```json
"product_overrides": {
  "15789": {
    "category": "17711",
    "columns": {"LF": 250, "LG": 8, "LH": 8, "LI": 15, "LA": 12}
  }
}
```

Стойностите в примера са само пример. Полетата са именувани с Excel колони: `LF` тегло g, `LG/LH/LI` размери cm, `LA` запас, `NY` производител, `NZ` EU responsible person, `LY` страна на произход. Категорията се задава чрез `category`, не чрез директна промяна на колона E.

`brand_manufacturers` задава точни производители по нормализирано име на марка. `eu_responsible_by_brand` работи аналогично, например `"natural factors": "Geo Nutrition LTD."`, **само когато тази връзка е потвърдена**. Стойността трябва да съществува в падащото меню за избраната категория.

## Локално стартиране

Python 3.11 или по-нов:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python revita.py --offline --output offline-output
python revita.py --refresh
```

При повторно локално изпълнение без `--refresh` се използват вече изтеглените HTML от `cache/`, за да може прекъснато изпълнение да продължи. За актуални цени и наличности използвай `--refresh` (workflow го задава автоматично). Пауза между заявките по подразбиране: 1.2 секунди; timeout 45 секунди и до 4 опита при временни грешки.

Проверките са локални върху предоставените HTML примери и синтетични гранични случаи. Целият жив каталог и валидността при реален Temu import ще се проверят след първото GitHub изпълнение.
